# Recall follow-up — 23 September 2026

**Decision: retain multilingual-e5-small. This pass did not improve production
recall.** Two larger offline models and query/chunking experiments did not yield
a consistent improvement across the drilling and regression examples. Rejected
ranking changes have been removed. The previous extraction/vocabulary fixes
remain in place; model files, scoring weights and schema are unchanged.

## Model comparison

The user authorized a larger offline model only if quality justified size and
speed. Each model was evaluated on the same 11 frozen inputs: the original
drilling posting in both languages, the 100-CV F&B set, four single-language
paired-career cases, and four mixed-language paired-career cases. The latter
use alternating career languages and the complementary assignment, one
translation per person. Their assignments were frozen before scoring.

This produced **33 completed model/case runs**. The six-career cases are repeated
measurements of the same fictional people, not eight independent populations.
All labels remain provisional synthetic judgments; human domain/translation
review is still pending.

| Model | Drilling recall@10 EN / AR | Strong fits in top three EN / AR | F&B recall@10 | Local model directory size |
| --- | --- | --- | --- | --- |
| Small, current | 75% / 75% | 1 / 1 | 62.5% | 129 MiB |
| Base | 75% / 75% | 1 / 1 | 75% | 282 MiB |
| Large | 50% / 50% | 1 / 0 | 62.5% | 552 MiB |

Base's F&B gain is real in this synthetic comparison, but its Arabic drilling
NDCG@10 falls from **0.7494 to 0.6486**, and the first strong candidate drops from
rank 1 to rank 2. Its mixed-language top-three results also include a regression.
Large reduces both drilling recall and Arabic top-three relevance. These costs
do not justify changing the default model.

These are **Node CPU, q8, batch-size-8** measurements with three serial warm
query repetitions, not measured desktop-app latency or whole-app memory.
Production uses Electron IPC and batches up to 32. File hashing warms the file
cache before model loading, so load time is not a cold-disk startup benchmark.
Memory is sampled every 25 ms. Model sizes include local configuration and
provenance files; verified runtime assets alone are 295,731,706 bytes for base
and 578,852,912 bytes for large.

The small-model benchmark reproduces all 11 production quality-metric sets.
Scores differ by up to 0.0101 with the different batching/runtime; the F&B order
also differs outside the measured relevance metrics. All model comparisons use
the same batch size, input hashes and production scoring bundle. No label or
filename is embedded or passed as a ranking feature.

Full metrics, sizes, timings, per-case tier-1 ranks, input hashes and model-file
checksums: [preserved comparison JSON](quality/2026-09-23/recall-models.json).
Detailed local results and source-text inputs remain under ignored
`eval/results/recall-2026-09-23/`.

## Other experiments and remaining causes

Distributing a fixed keyword budget across the whole posting and retaining
short labelled passages reduced F&B relevance in the exploratory combined
run. A full-term BM25 alternative also failed to recover that loss. Two general
edge cases were found during review: premature deduplication could erase a
repeated late requirement, and treating any short skills section as a full body
could discard a short career statement. Those experiments were corrected for
diagnosis and then removed rather than shipping a net regression. They do not
change the retained production sixty-term prefix limit or chunk policy.

Per-requirement diagnostics show that strong Arabic CVs can have nonzero raw
semantic similarity yet end up near the bottom of the normalized semantic
range, with no English lexical contribution. Unrelated assessment instructions
also become requirement queries, and exact skill mentions do not establish
ownership, relevant tenure or responsibility. Removing those instructions alone
is not demonstrated to solve the language gap. The existing
[matching diagnosis](MATCHING-FOLLOWUP-2026-09-23.md) remains open.

Two exploratory runs aborted when the optional diagnostic path repeated query
inference. The final diagnostic path captures the vectors and raw scores from
the actual search, performs no second inference, and excludes diagnostic work
from the recorded search time. Failed runs are not included in the model table.

## Retained engineering work

- `QUMAA_EVAL_DIAGNOSTICS=1` captures actual raw components and the winning
  passage for each query through an in-process evaluation hook. It exposes no
  renderer API and changes neither the ranking nor its weights.
- `QUMAA_EVAL_BENCH_INPUT=...` exports identical parsed inputs and SQLite scores
  for model-only comparisons. Output contains source text and must remain
  private when evaluating real CVs.
- [benchmark-model.mjs](../scripts/benchmark-model.mjs) runs offline models
  outside the app database, records hashes and resource measurements, and
  rejects malformed inputs. Model candidates remain separate from production.
- The mixed-language cohorts expose failures that single-language pools can
  hide. Their manifest is preserved in the comparison JSON.

The production build, **473 unit tests** and **250 Electron smoke checks** passed
after removing the rejected changes. A new integration assertion checks that
diagnostics make exactly one query-inference call and reproduce production
components and per-requirement averages. The full Arabic drilling evaluation
also completed with diagnostics enabled and retained its baseline metrics
(75% recall@10, 33.3% precision@3). CLI checks reject invalid tiers and input
overwrite, including aliases through symbolic-link directories. That final
output-path safeguard was added after the model runs; the exact benchmark
script used for their recorded hashes is retained locally as
`eval/results/recall-2026-09-23/benchmark-used.mjs`.
No installers were rebuilt in this pass.

## Reproduce

Build the app, then use the existing evaluator with its corpus/posting/label
overrides and `QUMAA_EVAL_BENCH_INPUT` pointing into an existing private directory.
For example, after exporting `drilling-en.json`:

```sh
node scripts/benchmark-model.mjs \
  --input eval/results/recall-2026-09-23/model-inputs/drilling-en.json \
  --model-dir resources/models \
  --model-id multilingual-e5-small \
  --output eval/results/recall-2026-09-23/repeat-small.json
```

For another model, supply a separate local model directory containing its
configuration, tokenizer and q8 ONNX file. The script never downloads a model or
changes the production model manifest. Retain the pinned hashes from the report
when preparing an alternative model directory.
